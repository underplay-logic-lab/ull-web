### 各機能の補足

**Multi-Angle**
- B200 が総合最有力（合計 69.8s vs B300 117s、cold が 7.7s vs 56.5s）。既定はすでに `["b200","b300"]`。
- 各 tier 1回のみの実測。B200 で 8構図を2〜3回回して再現性を見るのが残り（¥30/回）。
- cold が B300 に落ちた場合の粗利 50% は「最低3構図」で原価割れを防ぐ設計。

**超解像 画像**
- warm 20s なら粗利 73% だが **cold 60s だと 20%**。scaledown 30s の運用で単発利用が多いと
  cold 比率が高くなる。動画 HD の横断実測では RTX PRO 6000 が B300 の 1/5 のコストだった
  ので、静止画も同じ tier へ寄せられる可能性が高い。**1回の実測（¥10 程度）で決まる。**

**超解像 動画**
- 4K は B300 一択（VRAM 116〜135GB）。**所要時間が未実測**なので ×6.02 は HD/2K の比率からの推測。
  ローンチに含めるなら1本測る（¥200 程度）。

**Director**
- VRAM 129GB（Fast）で H200 も入らず B300 一択。原価 ¥8.8/秒（Fast）・¥15/秒（Quality）。
- 最大 60 秒 Quality = 1,542C = ¥2,560。**Pro の月付与 2,500C を1本で使い切る**。

**LoRA（ai-toolkit / B300）**
- GUI 既定（2000step）で **2,524C。Pro（2,500C）では1本も回せず、Master でも月2本**。
  価格が高いのではなく（fal 比 −23%）、ジョブが重い。プラン設計とのズレが最大の論点。
- 実測は minimax_h3 のみ。他 11 arch の s/it は推測値で、cost-guard が見積もりの約2.8倍まで
  耐えるので「殺される」事故は起きにくいが、推測が高すぎれば初回ユーザーが払いすぎる。

**LoRA SDXL（sd-scripts / L40S）**
- 実ジョブで 76%。校正不要。B300 での比較は未実施（急がない）。

**Custom workflow**
- DB に2行。`minimax-h3-fl2va`（100C・B300・**無効**）と `wan-animate-dance`（100C・**tier=l4**・有効）。
  Wan Animate は B300 級が要るはずで、`l4` は置き忘れの可能性が高い。Cinematic/Wan Animate
  タブは 2026-09-09 に廃止済み。**このタブ自体をローンチに含めるかが先**。

## 2. 決めること（ホスト判断）

1. **LoRA のベースモデル範囲**: 実測済みの minimax_h3 と SDXL 系（Illustrious / WAI / Juggernaut）
   だけで出すか、残り11 arch を推測価格のまま出すか。出すなら 200step の s/it 計測を
   arch ごとに1本（B300 で ¥150/本、11本で ¥1,650）。
2. **LoRA ジョブとプランのズレ**: GUI 既定を 2000→1000〜1200step に下げる／Pro の付与を増やす／
   「LoRA は Master 前提」と割り切る、のどれか。
3. **Director の最大尺 60秒**: 維持するか、Quality の上限を短くするか（1本で Pro を使い切る）。
4. **超解像 画像の tier**: B300 のままか、1回測って RTX PRO 6000 へ寄せるか（cold 時の粗利 20% を解消）。
5. **超解像 動画 4K**: ローンチに含めるか。含めるなら1本実測。
6. **Custom タブ**: ローンチに含めるか。含めるなら `wan-animate-dance` の tier と価格を実測で決める。
7. **粗利の基準**: 一律 3× markup（額面 67%・実質 57〜60%）でよいか。実質単価（ボーナス・手数料込み）
   で見るなら markup 3.5× 相当に上げる。USD/JPY 150 で計算した knob（Director・LoRA）は
   160 で引き直す（数分・GPU代ゼロ）。

### 価格思想（2026-09-23、ホスト明言・決定根拠）

**価格で勝負しない。** 一番は「他では出来ないこと」で、高いものがあってよい（それでも良ければ使って）。
それだけでは商売にならないので、**軽い設定（低解像度・少枚数・短 step）を選べば同じ価格式でそれなりに
安くなる**二層にする。LoRA も同じで、オートキャプション等の利便性が価値であり、競合の trainer と
単純比較される場所ではない。→ 上の「fal 比で高い/安い」は参考情報に格下げし、決定には使わない。
**解像度はユーザーに選ばせない**（ホスト判断、同日）。「512 を選んでいまいち」より「固定できれいに焼けた」
と思われる方が価値。固定値は arch ごとに最良の値を実測で決める（SDXL 1024。動画 arch はネイティブ 720p
前後なので 768 / 1024 を焼き比べて決める・未実施）。軽い設定（少枚数・短 step）は同じ式で自然に安くなる。

### 決定 6 に伴う設計課題（未着手）

- Wan Animate を Custom タブから独立させる。現行の `wan-animate-dance` 行は `default_gpu_tier=l4` で
  そのままでは動かない可能性が高い。60秒つなぎ合わせは Director と同じ「シーン連結」の枠で設計するか要検討。
- LoRA の per-arch GPU tier: 現在は app 全体で `GPU_REQUEST=["b300","b200"]` 固定。Modal 1.5.4 は
  `Function.with_options(gpu=…)` を持つので、dispatch 側で arch → tier を引いて spawn すれば
  再デプロイ無しで切り替えられる。SDXL は既に別ワーカー（L40S）。
